# Регексп по транскрипту без проверки происхождения выдумывает задачи-призраки

Транскрипт сессии содержит не только то, что **сделал** Claude Code, но и всё, что агент
**прочитал**: исходники, тесты, документацию, вставленные пользователем логи. Регексп,
шарящий по сырому тексту, не отличает «Claude Code запустил агента» от «агент открыл файл,
где эта строка просто написана».

## Правило

Событие засчитывается, только если пришло **как результат реального вызова инструмента**:
сопоставь `tool_use_id` результата с записью `tool_use`, у которой правильное `name`
(`Agent`, `Bash`, …). Совпадения текста самого по себе **недостаточно**.

## Инцидент (2026-07-13)

`subagent-watchdog` искал баннер `Async agent launched successfully … agentId: …` по всему
тексту. Агент, который **аудировал сам watchdog**, открыл его тестовую фикстуру —
и watchdog вычитал оттуда строковый литерал `agentId: a6`, придумал себе несуществующую
задачу и заблокировал Stop. Рядом в транскрипте лежал и его собственный регексп-детектор,
тоже как текст. Инструмент самоподорвался при чтении своих же исходников.

Симметричный дефект того же класса: ошибка разбора stdin (UTF-8 BOM, который Windows-шеллы
добавляют в пайп) роняла `JSON.parse`, а `catch` молча возвращал «всё хорошо». Сторож
одновременно умел **выдумывать несуществующую работу** и **тихо выключаться** на кривом входе.

## Чеклист

- [ ] Каждое «событие» из текста имеет провенанс: `tool_use_id` → `tool_use.name`
- [ ] Прочитанный/вставленный текст не может породить состояние
- [ ] Ошибка разбора входа не приводит к тихому «всё чисто»
