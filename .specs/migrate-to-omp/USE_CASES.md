# Use Cases

## UC-1: Install and activate the root plugin

**Feature tag:** @feature1

A maintainer adds the repository marketplace to a disposable project, installs dev-pomogator@stgmt, reloads skills and MCP, starts a fresh session, and proves the root extension and one registered capability are active.

## UC-2: Run authoritative readiness from OMP

**Feature tag:** @feature2

A spec author invokes the OMP wrapper against a broken fixture. The wrapper delegates to the existing verdict and returns a located NOT_READY result; a non-green phase confirmation is refused.

## UC-3: Produce migration evidence in Docker

**Feature tag:** @feature3

A release engineer selects the OMP Docker profile. The runner discovers the migration feature, step definitions and the single tagged lifecycle hook, then stores canonical scenario evidence.

## UC-4: Enforce a mapped OMP guard

**Feature tag:** @feature4

A safety owner selects one approved legacy guard from the matrix. Its OMP event receives a disallowed input, returns the declared block/reason response, and leaves the target document unchanged.

## UC-5: Roll back a failed wave

**Feature tag:** @feature5

A migration operator forces a disposable W1 failure. The W0 runbook disables the disposable OMP path, removes only allowlisted state, verifies a sentinel spec is unchanged, and confirms the Claude path still works.

## UC-6: Use the existing MCP door from OMP

**Feature tag:** @feature6

An agent user opens a fresh installed-plugin session, discovers dev-pomogator-specs through root .mcp.json, reads a spec, submits an invalid mutation, receives findings, and observes no target write.
