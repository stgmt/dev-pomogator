# Acceptance Criteria

## AC-1 (FR-1): Root install and activation

**Feature tag:** @feature1

**Требование:** [FR-1](FR.md#fr-1-root-marketplace-distribution)

WHEN a disposable project installs dev-pomogator@stgmt from the root catalog THEN the resolved source SHALL be the repository root; after reload and fresh session the root extension SHALL be loaded and a registered capability SHALL execute.

## AC-2 (FR-2): Authoritative delegation

**Feature tag:** @feature2

**Требование:** [FR-2](FR.md#fr-2-authoritative-engine-delegation)

WHEN an OMP wrapper evaluates a fixture with broken traceability or submits an invalid mutation THEN it SHALL return the authoritative NOT_READY or validation refusal and SHALL NOT create a second status or write path.

## AC-3 (FR-3): Docker lifecycle evidence

**Feature tag:** @feature3

**Требование:** [FR-3](FR.md#fr-3-docker-installed-plugin-evidence)

WHEN a migration scenario runs through the declared Docker profile THEN the profile SHALL discover its feature, steps and @migrate-to-omp lifecycle hook, and the resulting per-scenario record SHALL be ingested as canonical evidence.

## AC-4 (FR-4): Hook mapping behavior

**Feature tag:** @feature4

**Требование:** [FR-4](FR.md#fr-4-complete-hook-contract-matrix)

WHEN an in-scope guard is enabled in OMP THEN its mapping SHALL identify event, result and headless policy, and its regression scenario SHALL prove the declared block or output behavior without invoking a Claude-shaped callback API.

## AC-5 (FR-5): Rollback preservation

**Feature tag:** @feature5

**Требование:** [FR-5](FR.md#fr-5-w0-bounded-rollback)

WHEN a disposable migration wave fails THEN rollback SHALL remove only allowlisted fixture and project-scope OMP state, preserve an unrelated sentinel spec byte-for-byte, and leave the Claude path usable.

## AC-6 (FR-6): MCP discovery and refusal

**Feature tag:** @feature6

**Требование:** [FR-6](FR.md#fr-6-portable-mcp-door)

WHEN a fresh installed-plugin OMP session discovers dev-pomogator-specs THEN it SHALL expose the resolved launcher/root contract; an invalid apply_spec_change request SHALL return findings and SHALL leave the target file unchanged.
