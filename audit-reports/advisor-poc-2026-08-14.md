**Дата:** 2026-08-14 · **Репозиторий:** dev-pomogator · **Статус:** PoC (не спека)

## 2. Что такое «стоковый антропик адвизор» (ground truth)

По официальной документации Claude Code (`/docs/en/advisor.md`):

- **Принцип:** модель-пара «executor + advisor». Основная модель сама решает, когда зовёт
  вторую (обычно более сильную) модель.
- **Ключевые точки консультации:** (1) перед выбором подхода, (2) при застревании на
  повторяющейся ошибке, (3) перед объявлением «всё готово». Тайминг model-driven, не rule-based.
- **Что получает адвизор:** полный диалог включая каждый tool call и результат.
- **Что возвращает:** guidance, который основная модель применяет перед продолжением.
  Если её собственные данные противоречат совету — модель показывает конфликт, а не следует вслепую.
- **Поведение в сессии:** строка `Advising` (Ctrl+O раскрывает guidance), приблизительно
  2 засечки на решение, не на каждый ход. Non-blocking по своей природе (это совет, не гейт).
- **Стоимость:** только затраты на вызовы (advisitor reads conversation fresh; кэш не переиспользуется).

**Критичное ограничение для нас:** стоковый адвизор — **server-side tool** (исполняется на
инфраструктуре Anthropic, beta `advisor-tool-2026-03-01`, `advisor_20260301`), требует
Anthropic API + feature-flag (`DISABLE_TELEMETRY` вырубает). У нас транспорт — **не**
Anthropic API, а локальный антропик-совместимый прокси sub2api на gpt-5.6-sol/luna.
Поэтому нативный `/advisor` у нас не заведётся как есть → PoC реализует **клиентский аналог**:
тот же паттерн «вторая сильная модель смотрит диалог на ключевой точке» через наш стек.

## 3. Что построено

`tools/advisor/` (новое, untracked — PoC):

| Файл | Роль |
|---|---|
| `advisor_stop.ts` | Stop-hook (non-blocking). На ключевой точке зовёт gpt-5.6-sol через sub2api `/v1/messages` и возвращает `{decision:"approve", systemMessage:"🧭 Advisor (...): …"}` — совет виден в чате через канал системных сообщений, как стоковая строка `Advising`. |
| `bench/bench.ts` | Проверка: 7 синтетических сценариев триггеров (offline, без сети) + прогон детектора по 30 реальным транскриптам + live-замеры (латентность, токены, наличие guidance) по 3 ключевым точкам. |

**Логика детекции ключевых точек** (subset из доков, детерминированная, со skip
attachment-событий — иначе хвост транскрипта забивает hook-аттачментами и окно не видит tool_use):

1. `DONE_CLAIM` — финальное сообщение декларирует завершение (`готово|сделал|done|fixed|…`)
   И в окне были реальные tool_use.
2. `RECURRING_ERROR` — один и тот же error-signature в tool_result **≥2 раз** в окне.
3. `PLAN_APPROACH` — в окне есть `ExitPlanMode` / plan-tool.

**Fail-open по всему:** нет токена/эндпоинта/fetch/таймаут/HTTP!=-200/неразобранный ответ →
`{}` (молчаливый approve). **Anti-spam:** cooldown 5 мин на сессию + маркер; повторная
консультация уже-проконсультированного хода не делается. **Modes:** `true`/`shadow`/`false`.

## 4. Проверка (что реально прогонялось)

### 4.1 Offline-бенч детектора — 7/7 PASS

| Сценарий | Ожидание | Факт |
|---|---|---|
| done-claim fires | DONE_CLAIM | PASS |
| plain chat stays quiet | null | PASS |
| recurring error fires | RECURRING_ERROR | PASS |
| recurring error stale once stays quiet | null | PASS |
| plan approach fires | PLAN_APPROACH | PASS |
| done-claim without tool work → quiet | null | PASS |
| done with real mutating work | DONE_CLAIM | PASS |

Плюс прогон детектора по **30 реальным транскриптам** из `~/.claude/projects` (≤30 дней, <5MB):
честно сработал 1 DONE_CLAIM (реальная сессия mem-observer), остальные — молчат (что и
нужно: не спамить).

### 4.2 Live-вызов модели (sub2api → gpt-5.6-sol)

Три ключевые точки, реальный `/v1/messages` (thinking disabled, max_tokens 600):

| Ключевая точка | HTTP | Латентность | in/out токены | Guidance |
|---|---|---|---|---|
| DONE_CLAIM | 200 | 5 546 ms | 2 199 / 73 | ✅ «работа завершена; проверь одно: файл виден в `git status`» |
| RECURRING_ERROR | 200 | 6 249 ms | 672 / 284 | ✅ «не повторяй запуск; проверь `npm ls tsx`, lockfile, dev-deps» |
| PLAN_APPROACH | 200 | 6 102 ms | 2 194 / 279 | ✅ «зафиксируй контракт, пропиши unit-тесты, header/auth sub2api» |

Качество guidance — содержательное, предметное, с именами тулзов и конкретными шагами.
Латентность ~5.5–6.3s — заметная, но это PoC (стоковый тоже стоит токенов; для прода встанет
нужен свой бюджет и порог).

### 4.3 Ручной прогон Claude Code в dev-pomogator (end-to-end)

Команда:
```
claude -p --settings <overlay.json> --permission-mode bypassPermissions --model gpt-5.6-luna \
  "Создай файл tools/advisor/poc-probe4.txt … и напиши краткий отчёт что готово и что сделал."
```
- **Overlay** (`advisor-overlay.json`, вне репо) добавляет Stop-hook адвизора и глушит
  чужеродные гейты (`CLAIM_GATE_ENABLED=false`, `SPEC_ACCESS_ENFORCE=0`) — наблюдается только адвизор.
- **Файл создан**, хук отработал реально: fires-лог `kind=DONE_CLAIM`.
- В транскрипте сессии `abe82811-46d8-4954-8ed3-695aa7842462` появился hook-выход:
  `{"decision":"approve","systemMessage":"🧭 Advisor (DONE_CLAIM): - Работа выглядит
  завершённой: Write подтвердил создание … - перед окончательным завершением проверь одно:
  виден ли новый файл в git status …"}` — осмысленный, не спамовый совет.

### 4.4 Найденные при этом реальные грабли (полезны для будущей спеки)

1. **attachment-события засоряют хвост транскрипта.** Наивный `events.slice(-N)` на живом
   транскрипте видит после финального сообщения 10–15 hook-аттачментов и не находит tool_use →
   детектор молчал на `готово`. Фикс: фильтровать `type in {user, assistant}` перед окном.
   Это надо закрепить BDD-сценарием.
2. **Регекс русского рода**: «готова»/«создана» не ловились сигнатурой `готово` — расширил
   на `готова|готов\b|создан…`. Аналогичные родовые формы стоит перечислять явно.
3. **Латентность Stop-hook**: +5–6с к каждому Stop на консультации слишком дорого для
   «на каждый done». Стоковый адвизор дешевле из-за server-side; у нас нужно либо
   поднимать порог (консультировать не каждый done), либо асинхронно (поверх фонового
   задачи), либо кэшировать проконсультированные хэши ходов (уже есть cooldown).

## 5. Ревью: насколько это «так же хорошо как стоковый»

Критерий из вопроса — «чтоб так же хорошо как антропик адвизор стоковый». Честный расклад:

### Что совпадает с официальным паттерном
- ✅ Модель-пара: основная — gpt-5.6-luna, адвизор — gpt-5.6-sol (сильнее), как
  «Sonnet main + Opus advisor».
- ✅ Вторая модель получает bounded-срез диалога с tool calls и results (пакет `buildPacket`).
- ✅ Три официальные ключевые точки покрыты (done/recurring/plan).
- ✅ Non-blocking совет через `systemMessage` (аналог `Advising`), модель применяет сама.
- ✅ Адаптация: если совет противоречит фактам — модель вольна не следовать (у нас нет блокировки).

### Чем отличается (осознанные ограничения PoC)
| Аспект | Стоковый | Наш PoC |
|---|---|---|
| Исполнение | server-side tool на инфраструктуре Anthropic | клиентский Stop-hook, зовёт наш прокси |
| Полнота диалога | полный диалог всегда | bounded последние ~40 conv-событий (из-за токен-бюджета) |
| Тайминг | model-driven (модель сама решает «когда») | детерминированный детектор (когда → эвристики) |
| Стоимость | server-side, кэш не переиспользуется | платный вызов gpt-5.6-sol/ход, ~5-6s |
| Prompt-caching | свой | свой (не инвалидирует кэш основной модели) |
| Конфиг | `/advisor opus`, `advisorModel`, `--advisor` | env `ADVISOR_ENABLED/MODEL`, settings overlay |

### Вердикт
Как **доказательство концепции** — собран и проверен end-to-end: детектор не спамит,
model даёт содержательный и предметный совет на всех трёх ключевых точках, guidance реально
попадает в транскрипт Claude Code. Это **не** «стоковый адвизор в лоб» (тот на чужом
server-side API), но **тот же паттерн**, работающий на нашем стеке.

Чтобы претендовать на «так же хорошо», осталось (next steps):
1. **BDD** на детектор (фикстуры реальных транскриптов, включая attachment-хвост и родовые формы) —
   через spec авторинг (create-spec/дверь), как тут принято.
2. **Асинхронность/порог**: консультировать не каждый done, а редкие (cost-gated), чтобы не
   тянуть +5s на Stop; либо вынести в background.
3. **`/advisor`-подобная настройка** для юзера (skill/command), сохранение `advisorModel`.
4. **Bench на реальных задачах**: N прогонов claude с подсадкой ошибок, метрики
   catch/miss-подобно нашему live-run (уже готовая обвязка в `bench.ts`).
5. Решить судьбу: заводить спеку `advisor` в dev-pomogator или переносить в lm-saas
   (relay → всё же server-side аналог) — раздельно от PoC.
